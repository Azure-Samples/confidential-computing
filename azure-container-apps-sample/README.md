# Azure Container Apps samples

[Repository overview](../README.md)

Two implemented examples demonstrate explicit binding to a **confidential DC4
workload profile in UAE North**. The HTML quickstart also offers an explicitly
experimental West Europe option; the Functions workflow remains UAE
North-specific. Choose a guide based on the endpoint and
prerequisites you need:

| Sample | Status |
| --- | --- |
| [Confidential hello world](container-apps-acc/README.md) | ARM template and PowerShell deployment using DC4 in UAE North by default, with an explicit experimental West Europe option |
| [Functions on Azure Container Apps](functions-on-azure-container-apps/README.md) | Tested native Functions hello world on confidential DC4 in UAE North: Node.js 24, fresh ACR builds, managed identity, private Blob host storage, deployment and verification |

Start with **Confidential hello world**. It uses Microsoft's public quickstart
container image and does not require Docker, a private registry, or application
code changes.

Then follow the **[Functions deployment walkthrough](functions-on-azure-container-apps/README.md#start-here)**
to run application code on that confidential environment. It covers local
Azurite testing, scoped permissions, private storage networking, immutable image
deployment, host-health checks, and generating your own portal and API links.
The hello-world route is `GET /api/hello`, which returns JSON rather than an HTML
page.

## Deployment order and verification

1. Deploy and verify the [confidential environment and HTML quickstart](container-apps-acc/README.md#start-here).
2. Optionally add the [native Functions JSON endpoint](functions-on-azure-container-apps/README.md#start-here)
   to that environment and resource group. It can share the existing DC4 node.
3. Use each guide's placement and endpoint checks. For Functions, also confirm
   host-storage health and Blob lease acquisition; HTTP 200 alone is insufficient.
4. Use the portal and application links generated by your own deployment.

The base quickstart needs no image build or role assignments. Functions adds
ACR, managed identity/scoped roles, storage, and a Blob private endpoint with
VNet-linked DNS; it requires additional tools and role-assignment permissions.
Neither guide deploys the Azure App Service platform.

## Validate confidential-compute placement

Follow these checks for **each app**, including when both share one environment.
They implement the [Microsoft Learn verification procedure](https://learn.microsoft.com/azure/container-apps/confidential-compute#verify-your-confidential-compute-configuration):
read the app's assigned profile, then look up that exact profile's type in the
environment the app actually references. A profile merely named `confidential`
is not sufficient; its type must be a DC-series type. These examples require
**DC4** specifically, with no ordinary-compute fallback.

### Read-only PowerShell verification

Run from the repository root with PowerShell 7 and `Az.Accounts` installed.
Replace the subscription and group with your deployment values. Use
`ca-acc-hello` for the HTML example or `ca-functions-hello` for Functions
(or your customized app name), and the environment name you deployed.
This only reads Azure resources; it does not deploy or change them.

```powershell
$ErrorActionPreference = 'Stop'
$subscriptionId = '<your-subscription-id>'
$resourceGroup = '<your-dedicated-demo-resource-group>'
$environmentName = 'cae-acc-hello'
$appName = 'ca-acc-hello'
$location = 'uaenorth' # Use 'westeurope' only for the HTML quickstart experiment.

Connect-AzAccount -Subscription $subscriptionId
. .\azure-container-apps-sample\container-apps-acc\DeploymentHelpers.ps1
$resourceBase = "/subscriptions/$subscriptionId/resourceGroups/$resourceGroup/providers/Microsoft.App"
$app = Get-ArmJson -Path "$resourceBase/containerApps/${appName}?api-version=2025-07-01"
$environment = Get-ArmJson -Path "$resourceBase/managedEnvironments/${environmentName}?api-version=2025-07-01"
$appUrl = Assert-ConfidentialContainerApp -App $app -Environment $environment -Location $location
$assignedProfile = @($environment.properties.workloadProfiles |
    Where-Object name -eq $app.properties.workloadProfileName)
$revisionName = $app.properties.latestReadyRevisionName
$revision = Get-ArmJson -Path "$($app.id)/revisions/${revisionName}?api-version=2025-07-01"
if ($revision.properties.active -ne $true -or
    $revision.properties.runningState -notin @('Running', 'RunningAtMaxScale') -or
    $revision.properties.healthState -ne 'Healthy' -or
    $revision.properties.replicas -lt 1) {
    throw 'Expected an active, running, healthy revision with at least one replica; inspect revisions and replicas.'
}
[pscustomobject]@{
    AppId = $app.id
    EnvironmentId = $environment.id
    Location = $app.location
    AssignedProfile = $app.properties.workloadProfileName
    ProfileType = $assignedProfile[0].workloadProfileType
    MinimumNodes = $assignedProfile[0].minimumCount
    MaximumNodes = $assignedProfile[0].maximumCount
    LatestReadyRevision = $revisionName
    RevisionActive = $revision.properties.active
    Replicas = $revision.properties.replicas
    RevisionRunningState = $revision.properties.runningState
    RevisionHealthState = $revision.properties.healthState
    AppUrl = $appUrl
    CheckedAtUtc = [datetime]::UtcNow.ToString('o')
    Evidence = 'Azure-reported confidential placement, not hardware attestation'
} | Format-List
```

The shared guard **throws** unless the app references the expected environment,
both resources report `Succeeded` in the explicitly expected region, the assigned profile is
`confidential` with type `DC4` and minimum/maximum one node, and the latest
revision is ready. It also checks the examples' HTTPS ingress settings. The
additional revision read requires an active revision, at least one replica,
`Running` or `RunningAtMaxScale`, and `Healthy`. `RunningAtMaxScale` is normal
when the configured maximum replica count has been reached; it does not by
itself indicate a failure. If a check fails,
do not report successful confidential placement; inspect the named resource
and rerun after resolving the cause.

Expected output includes `AssignedProfile: confidential`, `ProfileType: DC4`,
`RevisionRunningState: Running` (or `RunningAtMaxScale`),
`RevisionActive: True`, at least one replica, and `RevisionHealthState: Healthy`, plus the
actual app/environment IDs and timestamp. Save that output if you need an
auditable configuration snapshot. Repeat with the second app name if deployed.
Run each guide's endpoint checks separately; Functions also needs its
[host-storage health checks](functions-on-azure-container-apps/README.md#5-verify-placement-http-response-and-host-storage).

### Cross-check in Azure portal

1. Open the **container app**, not just the resource group. In **JSON View**,
   note `properties.environmentId` and `properties.workloadProfileName`.
2. Open that exact environment and select **Workload profiles**. Match the
   assigned profile name and confirm its type is **DC4**. You can also inspect
   `properties.workloadProfiles` in the environment's JSON View.
3. Return to the app's **Revisions and replicas** view. Confirm the latest
   revision is ready and its replica is running. Repeat for the Functions app.
4. An additional `Consumption` profile in the environment is not a failure:
   what matters is that **this app** selects the DC4 profile, not Consumption.

### What this proves, and what it does not

These are live **Azure control-plane configuration and runtime-state checks**.
Microsoft documents an app assigned to a DC-series profile as running on
confidential compute infrastructure. An HTTP response, container image, app
name, private endpoint, or presence of an unused DC4 profile does not establish
that assignment.

The checks are **not independent cryptographic hardware attestation**. These
examples do not retrieve a hardware report, validate an attestation token or
release secrets based on attested claims. If your threat model requires that
evidence, this walkthrough alone does not meet it. Do not equate private Blob
storage connectivity or HTTPS with proof of a trusted execution environment.

## Cost and security boundaries

Both samples create billable resources and retain them until you explicitly
clean them up. Regional availability and quota must be checked in your own
subscription. Configuration verification is not independent hardware
attestation. The endpoints are public and anonymous; send no sensitive data.
Private Blob networking in Functions does not make its HTTP ingress private.

Deleting one app leaves the DC4 environment and other support resources
billable. Deleting the dedicated group removes all examples and supporting
resources in it. Review the inventory and the guide's cleanup instructions first.
